## 브라우저 검증 결과

### 검증 방법
Playwright 기반 headless browse 스킬을 사용하여 실제 HTML 파일을 브라우저에서 열고, 마이그레이션 탭의 카드 UI와 상호작용 동작을 검증했습니다.

### 검증 대상 및 결과

#### 1. Scenario 1: 인증서 체인 (정답: 예, 실패합니다)

**버튼 클릭:**
- @e18 버튼 "발생한다" 클릭

**렌더링된 정답 텍스트:**
```
정답 (tag)
예, 실패합니다.

근거: Key Vault에는 리프 인증서뿐 아니라 전체 인증서 체인(중간 인증서 포함)이 포함된 .pfx를 등록해야 합니다. 
체인이 빠지면 클라이언트가 인증서 신뢰 경로를 완성하지 못해 TLS 핸드셰이크가 실패할 수 있습니다.
```

**확인:** ✓ 정답과 근거 모두 정확히 표시됨

#### 2. Scenario 3: Rate-Limiting 윈도우 (정답: 아니요, 동일하지 않을 수 있습니다)

**버튼 클릭:**
- @e22 버튼 "발생한다" 클릭 (의도적으로 틀린 선택)

**렌더링된 정답 텍스트:**
```
정답 (tag)
아니요, 동일하지 않을 수 있습니다.

근거: APIM classic 티어의 rate-limit은 슬라이딩 윈도우 방식이지만 분산 아키텍처 특성상 완전히 정확하지 않을 수 있다고 
공식 문서에 명시되어 있고, v2 티어는 토큰 버킷 알고리즘을 사용해 classic과 계산 방식 자체가 다릅니다. 
Kong의 카운팅 정책(local/cluster/redis)과도 정확히 1:1로 일치한다고 가정하면 안 됩니다.
```

**확인:** ✓ 틀린 버튼을 눌러도 정답과 근거가 올바르게 공개됨
